# SUGRID 本机服务管理器

这是 Windows 本机服务管理器（运维控制台），用于管理项目的生产服务进程。默认端口为 `3000`，默认数据库为 `data/inventory.db`；由管理器启动的进程会显示实际数据库路径。外部启动的进程会标明“实际数据库未核实”，数据库备份、迁移和更新会被阻止，直到先接管进程或停止它。

## 启动

双击项目根目录的 `启动库存服务管理器.cmd`。窗口可随时关闭；Next.js 服务由独立进程运行。再次打开管理器时，它会按端口和进程命令行重新识别项目服务，并显示 PID、状态和日志位置。

首次部署需要先通过“安装依赖”“初始化数据库”“构建”，随后启动服务。日常使用可打开项目、检查 Git、备份数据库、构建并重启，或执行安全 Git 更新。

## Git 更新规则

- 只更新 `main` 到 `origin/main`，并使用 `git pull --ff-only`。
- 工作区存在已修改或未跟踪文件、分支分叉时会停止更新；不会 stash、reset、删除或覆盖文件。
- 更新前停止服务并通过 SQLite 在线备份 API 备份当前数据库，然后执行 `git pull`、`npm ci`、`npm run db:init` 和 `npm run build`。
- 更新步骤失败时不会假装成功；日志会保留在 `.tmp/server-manager/logs`，服务保持停止并显示失败步骤。

## Windows 启动模式

管理器直接启动并跟踪 Node.js 服务进程，适合当前账号登录后的手动启停与维护。要在无人登录时随系统启动，应安装成 Windows Service，并由 Windows Service Control Manager 管理。此项目不捆绑第三方服务包装器，也不会自动创建高权限系统服务。

管理器窗口会标明监听端口、主机地址、数据库文件、Git 分支和当前进程。外部服务可通过“接管 Next 进程”转由管理器启动；接管前应核对界面中的数据库路径。更新在拉取前失败时，管理器会尝试恢复原服务。若代码已经快进而安装、迁移、检查或构建失败，为避免运行不完整构建，服务会保持停止，并在操作记录和日志中保留失败步骤及数据库备份位置。

正式服务对局域网监听 `0.0.0.0`；请在 Windows 防火墙中只放行可信局域网所需端口。
