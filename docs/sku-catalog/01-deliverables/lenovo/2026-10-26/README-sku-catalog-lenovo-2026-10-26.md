## 2. 覆盖范围与口径

**覆盖系列**

- 轻薄本（42 条）：小新 Air（2016–2022）、小新 Pro 13/14/16（2019–2026）、小新数字系列（2018–2023）、小新 潮7000-13（2017）、YOGA（S730/C740/C940、13s/14s/16s、Air 13s/14s、Pro 13s Carbon/14s/16s、Air 14/14s/16、Air 14 Aura、Air 14s 骁龙）。
- 游戏本（48 条）：拯救者 Y7000/Y7000P/Y9000K/Y9000X、R7000/R7000P/R9000P/R9000K/R9000X、Y9000P 至尊版、GeekPro G5000，覆盖 2018–2026 各代。

**年份口径**：`modelYear` 取上市/机型年份（四位整数）。同一系列跨年不同代际按实际上市年份分行，未合并；跨年同名的机型（如 R9000X 2020/2021）在 notes 与「待核实与缺口」中说明判定依据。

**命名口径**：`model` 不含年份，显示名为「品牌 + 型号 + 年份」，例如「联想 小新 Pro 16 2024」。搜索「小新 Pro 16」可由 `brand=联想`、`model=小新 Pro 16` 命中。拯救者的系列名保留在 model 内（如「拯救者 Y7000P」），以保证搜索「拯救者」可直接命中。

**配置口径**：CPU/内存/显卡/存储/屏幕五个选项字段只写来源中有依据的值；没有证据的留空，不以常见配置补齐。内存统一为容量（如 16GB），来源中的代数/频率标注保留在备注。

**配置组合口径**：「配置组合」每行是一个来源证明确实销售过的搭配（官方规格页具体配置、京东具体 SKU 页、媒体首发配置与价格），通过「型号唯一键」关联主表；未做笛卡尔积，未臆造搭配。178 条组合覆盖 88 个型号；其余 2 个型号（拯救者 Y9000K 2019、Y7000 2020）只有独立选项、没有组合证据，已列入「待核实与缺口」。

**置信度规则**：high＝厂商官方页（lenovo.com.cn）或产品库规格页（中关村在线详情页/天极参数页/太平洋产品库）；medium＝媒体报道、百科、系列汇总页（仅凭百科作为主来源的 4 条已从 high 降为 medium 并注明）。本次没有 low 级数据混入主表。

## 3. 来源与可访问性

来源优先级：联想官网产品/知识库页 > 中关村在线产品库详情页 > 天极/太平洋产品库 > 京东自营规格页 > 媒体首发报道 > 百科（仅作交叉核验）。

138 个链接的检查结果（2026-10-26）：

- HTTP 200 可访问：130 个
- HTTP 403（百度百科反爬，浏览器可正常打开）：6 个
- HTTP 301 重定向（微信公众号文章）：1 个
- HTTP 405（天极参数页拦截自动化请求，浏览器可正常打开）：1 个

没有返回 404/410 的死链。可访问性结果逐条记录在「来源」工作表。

## 4. 已知缺口与阻塞点

1. **参考文件缺失**：调研简报提到「交接时提供的两个参考文件」，项目中只找到简报本身（`docs/sku-catalog-research-brief.md`），第二份未找到。因此本次采用临时范围：2016–2026 年联想消费级轻薄本与游戏本，与现有 ThinkPad 目录「2016 起」的口径对齐。
2. **不含 ThinkPad**：ThinkPad 已有 369 条 SKU，本次不重复收录；如需 ThinkPad 新机型，应单独补录。
3. **2016–2017 覆盖偏薄**：2016 年 2 条、2017 年 1 条（小新 潮7000-13）。2017 年的 YOGA 720/710、小新 Air 13 Pro 2017 等未检索到稳定规格页，未收录。
4. **2 个型号无配置组合**：拯救者 Y9000K 2019、Y7000 2020 主表有选项但缺「实际销售搭配」证据。建议用官方规格页或京东自营 SKU 页补齐。
5. **待核实 35 条**：含来源冲突 2 条、年份不明 3 条、配置/来源缺口 18 条、需人工确认 12 条，详见工作表。典型如「R9000X 2020/2021 跨年同名」「小新 Air 14 2020 酷睿版缺整机规格页」，以及 5 条主来源为产品库接口页/站内搜索页、建议替换为具体产品页的记录。
6. **价格不是采购价**：配置组合备注中的价格均为来源标注的首发价/参考报价（人民币，含日期），仅供核对，不能作为机器采购价。

## 5. 能否直接导入

**不能直接导入。** 项目现有 `scripts/import-laptop-skus.py` 只识别旧版 ThinkPad/小米工作簿（固定工作表名、固定 433 行校验），与本文件的通用结构不兼容。建议流程：

1. 用「SKU型号」表做字段映射（`productType/brand/model/modelYear/cpuOptions/ramOptions/gpuOptions/storageOptions/screenOptions`），多值字段按 JSON 数组解析。
2. 以「型号唯一键」对现有 `skus` 表做重复检查（品牌 + 型号 + 年份）。
3. 先导入预览、人工核对「待核实与缺口」中的 30 条，再单独执行数据库写入验证。
