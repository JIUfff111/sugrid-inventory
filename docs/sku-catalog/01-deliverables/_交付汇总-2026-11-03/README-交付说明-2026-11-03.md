# 笔记本 SKU 目录 · 全品牌交付汇总（2026-11-03）

这是 `01-deliverables/` 下 12 个品牌交付件的集中入口。想一次性看全量数据，只看本目录即可；想看单品牌内部口径与缺口说明，去 `分品牌/` 或各品牌原目录。

## 目录内容

| 文件 | 内容 | 规模 |
| --- | --- | --- |
| `sku-catalog-全品牌-2026-11-03.xlsx` | 全品牌总表，6 个工作表（说明 / 品牌统计 / SKU型号 / 配置组合 / 别名 / 待核实与缺口） | 659 型号 · 1945 配置 |
| `sku-models-全品牌-2026-11-03.csv` | 型号主表，UTF-8 BOM，可直接导入或做脚本处理 | 659 行 |
| `sku-configurations-全品牌-2026-11-03.csv` | 配置组合表，含「品牌」列便于筛选 | 1945 行 |
| `分品牌/` | 12 份单品牌工作簿原样副本（各自 6 个工作表，含该品牌口径说明） | 12 个文件 |

只提供表格（xlsx / csv），不含 PDF。汇总表与分品牌工作簿逐行一致，可互相校验。

## 总表工作表说明

- **说明**：口径、年份规则、置信度分级、导入状态等 20 条说明，先读这一页。
- **品牌统计**：16 个品牌线的型号数 / 配置数 / 置信度分布 / 来源链接数，末行为合计。
- **SKU型号**：一行一个型号，唯一键为 `产品类型|品牌|型号|年份`（17 列）。选项字段是 JSON 数组文本，如 `["i5-13500H","i7-13700H"]`。
- **配置组合**：一行一个**有来源证据的实际销售搭配**（13 列，比品牌表多一列「品牌」）。通过「型号唯一键」关联主表，没有做笛卡尔积。
- **别名**：828 条检索用别名（品牌全称、系列简称、电商标题写法等）。
- **待核实与缺口**：468 条未能进主表的型号 / 缺口说明，含问题类型、建议处理路径、来源文件，供后续补录。

## 数据来源与合并日期

- 各品牌取自己**最新一版**交付件：小米取 `2026-11-01`（与 `2026-10-26` 版逐行相同，只是重建日期不同），其余品牌取 `2026-10-26`。
- 合并后去重：型号按唯一键去重，配置按「同型号 + CPU/内存/显卡/存储/屏幕 五元组」去重，跨品牌无重叠（唯一键含品牌）。
- 来源共 1015 个去重链接，主要为厂商官网 / PSREF 产品页 / ZOL 与太平洋产品库 / 电商规格页。

## 与单品牌交付件的关系

| 场景 | 用哪个 |
| --- | --- |
| 横向比价、全量检索、一次性交付给业务方 | 本目录的全品牌总表 |
| 甲方只采购某个品牌，需要该品牌口径说明与缺口清单 | `分品牌/` 里对应工作簿 + 原目录的 `README-sku-catalog-<brand>-<date>.md` |
| 脚本批处理 / 导入数据库 | 本目录的两份全品牌 CSV |

原目录（`01-deliverables/<brand>/<date>/`）**保留不动**，仍是该品牌的权威交付位置。本目录是副本 + 合集，不是替代。

## 重新生成

```bash
cd web/docs/sku-catalog
python ../../scripts/sku-catalog/build_all_in_one.py
```

脚本会自动发现各品牌最新日期目录，重建全品牌 xlsx 与两份 CSV；`分品牌/` 的副本需按需重新拷贝（脚本不覆盖）。

> 注意：总表被 Excel / WPS 打开时无法覆盖同名文件（Windows 文件锁），重建前先关闭。

## 已知缺口

- 待核实 468 条集中在联想系（老款 ThinkPad 无 PSREF key）与戴尔 / 微星（官网反爬，只收 high 口径导致大量型号无法验证）。
- 型号 659 与调研数据集 660 差 1 条：该条置信度为 low，按规则移入待核实，未进交付主表。
- 不能直接导入正式库：`import-laptop-skus.py` 只识别旧版 ThinkPad / 小米工作簿格式，需先做字段映射与导入预览（见 `web/scripts/import-sku-deliverables.py`）。
