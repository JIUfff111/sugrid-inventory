# 采购 SKU 型号资料搜集说明

## 任务目标

为「溯格」采购中的 SKU 选择器补充可信、可追溯的笔记本电脑及其他已确认设备型号资料。型号必须带正确的品牌和型号年份，搜索和选择结果应能直接显示为「ThinkPad X13 2020」这类完整名称；配置选项应来自资料来源，不能用猜测补齐。

请先检查交接时提供的两个参考文件以及项目现有资料，识别已有型号、字段和来源，再补充缺失内容。不要重复造已有记录；发现来源冲突、年份不明或型号有别名时，记录下来并标明证据。

## 当前系统字段

系统现有 SKU 记录包含：

| 字段 | 要求 |
| --- | --- |
| `productType` | 产品类型，例如「笔记本电脑」「平板电脑」。保留中文分类名。 |
| `brand` | 选择器展示的品牌或产品线名称，例如 `ThinkPad`、`小米`、`Redmi`。同一分类中保持名称统一。 |
| `model` | 型号主体，例如 `X13`、`T14 Gen 3`、`MacBook Air 13-inch`。不要把年份重复写进型号字段。 |
| `modelYear` | 型号对应的上市/机型年份，使用四位整数；未知时留空，不要推测。它不是机器生产日期或采购日期。 |
| `cpuOptions` | 该型号有来源依据的处理器选项，保留正式型号名称。 |
| `ramOptions` | 有来源依据的内存容量选项；如焊接内存、插槽扩展或不同容量组合有影响，请在配置组合页记录。 |
| `gpuOptions` | 有来源依据的显卡选项；集成显卡与独立显卡应区分。 |
| `storageOptions` | 有来源依据的存储容量/类型选项，例如 `512GB SSD`。 |
| `screenOptions` | 有来源依据的屏幕尺寸、分辨率或面板选项，写清具体含义。 |
| `sourceUrl` | 支持该型号和配置的来源页面链接，优先官方产品规格/服务手册。 |
| `sourceTitle` | 来源页面或文件名称。 |
| `checkedAt` | 核验日期，格式 `YYYY-MM-DD`。 |
| `confidence` | `high` / `medium` / `low`；低置信数据应进入待核实清单，不应混入可直接导入表。 |
| `notes` | 别名、年份判定依据、缺少的配置信息、来源冲突等。 |

目前选择器把 CPU、内存、显卡、存储和屏幕分别作为独立选项，并不描述它们之间的有效搭配。因此必须额外交付一个「配置组合」工作表：每行代表一个有来源依据的实际配置组合，并包含对应型号唯一键和来源。不要将独立选项做笛卡尔积，也不要暗示系统能阻止用户选出未实际销售的组合。

## 搜集范围与规则

1. 以交接的两个参考文件中明确的品牌、产品类型、年份范围为准；参考文件不可用时，在交付说明中列出这个阻塞点和所采用的临时范围。
2. 对每个型号记录完整展示名拆分后的品牌、型号和年份。示例：`brand=ThinkPad`、`model=X13`、`modelYear=2020`，显示名为 `ThinkPad X13 2020`。
3. `brand` 不得留空；型号名称不得只保留容易重复的系列简称。不同年份或代际只有在来源确认是同一机型时才可合并。
4. 优先使用厂商官方产品页、规格页、维护手册、PSREF 等一手资料；可用可靠公开数据库交叉核验。每个型号至少提供一个可访问来源；配置组合尽可能提供具体到该配置的证据。
5. 标注「上市年份」「机型年份」「资料年份」中实际使用的年份概念。无法区分时留空并说明，不要把网页发布日期直接当作型号年份。
6. 保留官方型号名和常见搜索别名。别名放在单独字段或工作表，不要污染 `model` 正式字段，也不要把相似型号自动合并。
7. 价格不是本次必需字段。采购价由使用者针对每台实物录入；若来源带建议零售价，可放入备注并注明地区、币种和日期，不能作为机器采购价。
8. 不收集或编造 SN、IMEI、购买人等单机信息。SKU 是型号目录，不是库存机器档案。
9. 对没有证据支持的配置使用空值并列入缺口清单，不要以常见配置替代事实。

## 交付物

请一次性交付以下文件，使用 UTF-8 编码，并在文件名中标注来源和日期：

1. **`sku-catalog-YYYY-MM-DD.xlsx`**：主交付文件，至少包含以下工作表：
   - `SKU型号`：每个「产品类型 + 品牌 + 型号 + 年份」一行，包含本说明中的系统字段和来源字段。
   - `配置组合`：每个来源确认的 CPU、内存、显卡、存储、屏幕组合一行，关联型号唯一键并提供来源。
   - `别名`：常见搜索写法、官方写法、对应型号唯一键及别名来源。
   - `来源`：来源标题、URL、来源类型、覆盖字段、核验日期及可访问性结果。
   - `待核实与缺口`：年份不明、配置缺失、来源冲突、范围外型号等问题及建议处理方式。
2. **CSV 导出**：至少提供 `sku-models.csv` 和 `sku-configurations.csv`，UTF-8 编码，表头与 Excel 工作表一致；多值选项使用 JSON 数组文本或另附字段映射说明，不能用逗号分隔导致字段歧义。
3. **`README.md`**：说明覆盖的产品类型、品牌、年份范围、搜集和去重方法、来源优先级、已知缺口、统计口径及是否能直接导入。
4. 若参考资料包含可合法再分发的原始表格，请一并交付原文件；若不能再分发，交付稳定来源链接、文档标题和必要的字段摘录/证据说明，不要复制受限制的完整内容。

## 验收标准

- 每条可导入型号都有非空产品类型、品牌、型号；明确的年份使用四位整数。
- 型号唯一键 `productType + brand + model + modelYear` 无重复；不同年份未被错误合并。
- 搜索 `ThinkPad X13` 能由 `brand=ThinkPad`、`model=X13` 命中，界面组合后能显示完整品牌名和年份。
- 每个可导入型号至少有一个一手来源或明确的交叉核验说明；来源链接和核验日期可追溯。
- 配置组合与型号主表可通过唯一键关联；未证实的 CPU、内存、显卡、硬盘或屏幕搭配没有被臆造。
- 有单独的待核实清单；置信度低的数据不混入可直接导入数据。
- Excel 与 CSV 记录数一致，中文、年份、型号代际和多值字段在导出/重开后不丢失。

## 当前导入限制

项目现有 `scripts/import-laptop-skus.py` 只读取特定格式的 ThinkPad 与小米工作簿，并对源表行数和工作表名称有固定校验。它不能直接导入本说明的通用交付文件。请先交付资料，不要直接修改或写入正式数据库；收到文件后会再做字段映射、通用导入预览、重复检查和单独数据库验证。
