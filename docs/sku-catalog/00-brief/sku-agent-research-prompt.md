# 外部 SKU 搜集 Agent 提示词

复制以下提示词，并将方括号内容替换为本次任务信息。发送时同时附上 `sku-agent-handoff-standard.md`、`inventory-sku-entry-standard.md` 和当前 `builtin-sku-catalog.json`。

```text
你负责为“溯格”整理一批可审查、可导入的 SKU 目录增量。请遵守随附的《SKU 外部 Agent 交付标准》和《库存 SKU 录入与展示标准》。

本次范围：
- 产品类型：[例如：笔记本电脑]
- 品牌 / 系列：[填写]
- 年份或具体型号范围：[填写]
- 重点搜集项：[新增型号 / CPU、内存、显卡、存储、屏幕配置补全]
- 用户提供的参考资料：[列出文件名]
- 本次日期：[YYYY-MM-DD]

工作要求：
1. 先查看当前内置 SKU 快照和项目规则，按 productType|brand|model|year 识别已有记录。只把真正的新型号或新选项写入 sku-models.csv；已存在的写法、选项不要重复报成新增。
2. 优先找厂商规格页、服务手册、PSREF 等一手来源。每条型号和配置都能追溯到 sources.csv 的 sourceId；检查链接可访问并记录核验日期。
3. 输出原始证据与规范值：model/cpu/ram/gpu/storage/screen 使用项目标准；sourceBrand、sourceModel、sourceYearText 和 *Raw 字段保留原始资料写法。品牌单独存放；model 保留官方正式型号主体和系列名，不要额外重复拼接品牌或年份；完整展示名不得重复品牌或年份。
4. 小米、Redmi、红米在内置 SKU 中统一使用 brand=小米，系列名仍按正式型号填写；游戏本归产品类型“笔记本电脑”。CPU、GPU、内存和屏幕规范以随附标准为准。
5. 配置组合只列来源证明的真实组合，不做笛卡尔积。没有证据的字段留空或 []，不要按同系列、相邻年份或常见配置推测。
6. 低置信、年份不清、来源冲突、重复别名和超出本次范围的内容只列入 review.csv，不放进可导入增量。
7. 不收集单台机器的 SN、IMEI、采购价、供应商或库存数据；不修改项目代码、数据库、Git 或正式 SKU 文件。

必须交付一个文件夹（也可打包 ZIP），包含：
- README.md：范围、去重基线、方法、来源优先级、统计和已知缺口
- sku-models.csv：使用标准模板表头，只含真正的新增型号 / 选项增量
- sku-configurations.csv：有证据的实际配置组合，附原始值和来源 ID
- sources.csv：完整来源索引
- review.csv：冲突、重复、低置信和排除项；没有时保留表头并在 README 说明 0 条

CSV 必须 UTF-8，JSON 数组写为合法 JSON 文本。保留模板表头，不要合并单元格或把多个型号塞进一个单元格。README 必须报告每个文件的行数、唯一型号数、配置数、来源数、重复数和待核实数。

完成前自检：无重复唯一键；每个 sourceId 都存在；年份格式正确；选项数组可解析；品牌与产品类型遵循规则；所有“新增”已与所附内置目录比对。若无法访问内置目录或来源，请明确标记阻塞点，不得宣称完成去重或可直接导入。

最终回复只需给出交付文件夹 / ZIP 和简短统计，不要把完整表格贴在对话里。
```
